# Reset Password API Documentation

## Overview
The `/reset-password` endpoint is used to reset the user's password. It accepts a reset token (received from the forget-password endpoint and sent via email) and a new password. The endpoint decodes the token, verifies the user, and updates the password.

## How It Works

### Step-by-Step Process:

1. **Receive Request** - Accept token and newPassword from request body
2. **Verify Token** - Validate the reset token signature using JWT secret
3. **Check Expiration** - Ensure token has not expired (10-minute window)
4. **Decode Token** - Extract userId from token payload
5. **Find User** - Query database for user by userId
6. **Verify User Exists** - Ensure user is found in database
7. **Check User Status** - Verify user is not blocked
8. **Hash Password** - Hash new password using bcrypt
9. **Update Database** - Store hashed password and update passwordChangedAt timestamp
10. **Return Success** - Confirm password reset was successful

## JavaScript/Fetch Example

```javascript
const resetPassword = async (token, newPassword) => {
  try {
    const response = await fetch('http://localhost:3000/api/v1/auths/reset-password', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        token,
        newPassword,
      }),
    });

    const data = await response.json();
    
    if (data.success) {
      console.log('✅ Password reset successfully!');
      // Redirect to login page
      window.location.href = '/login';
    } else {
      console.error('❌ Reset failed:', data.message);
    }
  } catch (error) {
    console.error('Error:', error);
  }
};

// Usage from reset password page
// Extract token from URL
const urlParams = new URLSearchParams(window.location.search);
const token = urlParams.get('token');
const newPassword = document.getElementById('newPassword').value;

resetPassword(token, newPassword);
```

## Security Considerations

### Token Expiration
- Reset tokens expire after **10 minutes**
- Token includes creation timestamp (`iat`) and expiration (`exp`)
- Expired tokens will be rejected with 401 error

### Token Validation
- Token is signed with JWT secret
- Invalid or tampered tokens will be rejected
- Token is verified before decoding

### Password Security
- New password is hashed using bcrypt before storage
- Plain passwords are never stored in database
- Password hash uses 10 salt rounds for security

### User Verification
- User status is checked (blocked users cannot reset)
- User must exist in database
- userId from token is used to find user

### No Password in Response
- Response never includes password or token
- Only confirmation message is returned

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| "Reset token is required!" | Missing token in body | Include token field in request body |
| "Invalid reset token!" | Token is malformed or tampered | Get new token from forget-password email |
| "Reset token has expired!" | Token is older than 10 minutes | Request new reset via forget-password |
| "User not found!" | User ID in token doesn't exist | Check database for user |
| "This user is blocked!" | User account is blocked | Contact admin to unblock |
| "Password reset successfully!" but can't login | Password not actually updated | Try reset again or contact support |

## Common Questions

**Q: Where do I get the reset token?**
A: The token is sent via email when you call `/forget-password`. Extract it from the email link or copy from the link parameter.

**Q: How long is the reset token valid?**
A: The reset token is valid for 10 minutes. After that, you need to request a new one via forget-password.

**Q: What if I get token expired error?**
A: Request a new password reset via the forget-password endpoint, then try again.

**Q: Is my password encrypted?**
A: Yes, passwords are hashed using bcrypt with 10 salt rounds before being stored in the database.

**Q: Can I use the same token twice?**
A: No, the token is only valid for the first successful reset. For another reset, request a new token.
